## [Unreleased]

### Added

- **Enterspeed Context Graph** node and **Enterspeed Context Graph API** credential (ingest URL and Ingest API Key, delivery URL and Delivery API Key, manifest version). Each key is sent only to its own service. Neither URL has a default, so a Context Graph key never goes to an Enterspeed Core host. The credential test reads the manifest document from the Delivery URL with the Delivery API Key. **Entity — Push** sends each input item, as the record it is, to the Context Graph (`POST {Ingest URL}/v1/entities`), one request per item. Entity ID, Entity Type, Source, Action and Modified At set the record's `$id`, `$type`, `$source`, `$action` and `$modifiedAt`, each defaulting to the record's own. **Entity — Push Many** sends a list of records held in one item (e.g. from an Aggregate node) in one request; each record keeps its own `$` fields. Both output one accepted/rejected result per record.
- **Enterspeed Context Graph — Shape — Get / Get Many**: read the graph's shapes by shape key (e.g. `productPage:id:42`). *Get* takes one key per item and reads one shape per request (`GET {Delivery URL}/shapes/v1/{Manifest Version}/…`), outputting it as returned; a key with no shape fails the item. *Get Many* takes one item holding a list of keys (e.g. built in a Code node) and reads them in one request (`POST {Delivery URL}/shapes/v1/{Manifest Version}`), outputting `{ key, status, data }` per key, with a missing key as `status: 404`, `data: null`. The Tonevik demo workflow and guide now read back each step's shapes.
- **Enterspeed Context Graph — Index — Query**: query an index with filters, sorting and paging (`POST {Delivery URL}/query/v1/{Manifest Version}`). Each input item is one query; all are sent in one request (several only past delivery's 32 KiB body limit, with each query's position among the queries sent as its id), and each item gets back its result as returned (`{ id, index, items, totalCount, next }`). The Tonevik demo gains step 4, querying the product index.
- **Enterspeed Context Graph — Index — Query: Return All** (off by default): fetches every page of each query by sending it again with `cursor` set to its last `next` until `next` is `null`, and outputs one result per query with every page's matches in `items`. A query that sets `page` fails before sending, and one whose `next` repeats fails instead of looping.
- **Enterspeed Context Graph — Index — Get**: read one document from an index by its ID (`GET {Delivery URL}/query/v1/{Manifest Version}/{Index Name}/{Document ID}`), one per item, outputting it as returned. Document ID defaults to the item's `$id`, so a query's matches can be read one by one. A missing document fails the item. The SDK dev-server doesn't serve this read yet.
- **Enterspeed Context Graph — Representation — Get**: read the representation served for a route (e.g. `/products/42`), one route per item and one request each (`GET {Delivery URL}/v1/{Manifest Version}{Route}`). Outputs the representation as returned: each slot at its name, plus `$metadata` with each slot's `$state`. A partly resolved representation succeeds, with the unresolved slots `null`; a route with no representation fails the item. The Tonevik demo gains step 5, reading the product representation.
- **Enterspeed Context Graph — Schema — Get**: read the manifest's schema (`GET {Delivery URL}/schema/{Kind}/v1/{Manifest Version}`) as the materialised schema (MSD), OpenAPI 3.1 or JSON Schema, optionally only the routes under a prefix. Read once per run and output as one item.
- **Enterspeed Context Graph — fields filled from the schema**: Index — Get and Index — Query's new *Builder* mode pick the index, filter and sort fields and operators from the manifest's schema; Representation — Get's new *Schema* mode picks the representation and route and lists the context values it takes (path, query string or `X-Delivery-<name>` header). The *Route* field takes only a path: a route with `?` or `#` fails before sending. The schema is read only while the node is edited; the choices are saved in the workflow, so runs don't read it. The JSON query and the *Route* field remain the defaults. Shape — Get's *Schema* mode waits on the schema listing entry shapes.
- **Enterspeed Context Graph — Representation — Get: Resume Partial Answers** (off by default): an answer carrying `$metadata.$resume` is read again with the checkpoint in `X-Resume`, and each round is merged in by slot name, up to *Max Rounds* (default 3). Before a round the node waits for the open slots' `$timeoutMs`, up to *Max Wait Between Rounds*. A slot that needs a claim is not resumed. A refused checkpoint is answered once by reading the route again without it.
- **Enterspeed Context Graph — Artifact — Upload**: upload a snapshot source's complete export (a CSV or NDJSON file from the item's binary data) as it is, one file per item. The node reserves the upload (`POST {Ingest URL}/v1/sources/{Source}/artifacts`) with *As Of* (when the export started), *Row Count* (as the source reports it) and the file's SHA-256, uploads the file to the signed URL it is given (without the API key), commits it, and outputs the artifact as returned. The same file with the same *As Of* is recognised as a retry. A refusal fails the item with the Context Graph's own title and reason (e.g. `push-source`, `as-of-not-later`, `field-map-required`).
- **Enterspeed Context Graph — Artifact — Get / Get Many / Get Lines**: see what became of an upload. *Get* reads one artifact (`GET {Ingest URL}/v1/sources/{Source}/artifacts/{Artifact ID}`) and outputs it as returned: its state, drain result, deletions and first page of lines. *Get Many* lists a source's artifacts, newest first, optionally only in one *State*, up to *Limit* or all of them (following `nextCursor`). *Get Lines* outputs each record that was refused, failed or didn't parse as its own item, `{ number, outcome, type, id, reason }`, up to *Limit* or all of them (following `nextAfter`). The node doesn't wait for a drain; use a Wait node. Refusals fail the item with the Context Graph's own title and reason (`not-found`, `invalid-listing`).
- **Enterspeed Context Graph — Representation — Get: skip unchanged representations** (both off by default): *If-None-Match* sends an ETag kept from an earlier run (e.g. `{{ $json.etag }}`), and an unchanged representation's `304 Not Modified` succeeds as `{ notModified: true }`. *Include Response Headers* outputs each item as `{ status, headers, body }`, with whichever of `ETag`, `Cache-Control`, `Cache-Tag` and `Vary` the Context Graph sent, and a `304` as `{ status: 304, headers, body: null }`. Only a complete `200` carries an ETag; a partial answer, a resume round or an error carries none.
- **Enterspeed Context Graph — a busy Delivery is retried once**: when Delivery answers a read `503` (Shape — Get / Get Many, Index — Query / Get, Representation — Get and its resume rounds), the node waits `X-Delivery-Retry-After-Ms`, else `Retry-After`, plus up to a second of jitter, and sends the same request once more. A wait over 30 seconds, no wait, or a second `503` fails the item with a message saying Delivery is busy.
- **Context Graph: resume a partial representation** example workflow (`workflows/templates/Context-Graph-Resume-Partial-Answers.json`): reads the schema, picks a representation and its route, finds a document in the index over the route's model and fills the route from its `$rawId`, then reads it with Representation — Get twice, with *Resume Partial Answers* off and on, and lists each slot's `$state` and whether a checkpoint is left. It runs against Tonevik stage 1 on the SDK dev-server started with `budgetCut`.
- **Context Graph: upload exports** example workflow (`workflows/templates/Context-Graph-Upload-Stride-Exports.json`): a form picks one of the Stride demo shop's stored exports, fetches its files and `exports.json` facts, and uploads each file as it is with Artifact › Upload (products as NDJSON, categories as CSV), then reads back the shoe count and a removed shoe. Its three exports show a new product, a deletion by absence, and a cut-off file whose row-count mismatch voids its deletions.
- **Context Graph: round trip** example workflow (`workflows/templates/Context-Graph-Round-Trip.json`): every night it fetches a source's complete export and its facts (`asOf`, `rowCount`), uploads it as it is with Artifact › Upload, waits for the drain with Artifact › Get and a Wait node, and reads the result back with Index › Query. A line the graph refused or couldn't parse stops the run with the graph's own reason (from Artifact › Get Lines). No Code node. CI's e2e job runs it in Docker n8n against the SDK dev-server (`e2e/`), with Delivery's `304` and a `503` retry checked through n8n's real request helper; it needs `@enterspeed/dev-server` `0.2.0-alpha.4`, the first alpha with ingest's `/v1` routes, published.
- **Context Graph: Tonevik demo** example workflow (`workflows/templates/Context-Graph-Tonevik-Demo.json`): the Tonevik demo shop's PIM categories, products and a retired product, pushed step by step with Push Many against the local dev-server, with a guide (`docs/context-graph-demo/GUIDE.md`). `scripts/setup.mjs` now creates an Enterspeed Context Graph credential (local dev-server by default).

### Changed

- **Enterspeed Context Graph — Index — Query** sends a sort as `direction` `asc`/`desc`, the form the Context Graph's query contract names, in the Builder, the JSON example and the Tonevik demo. A Builder sort saved as Ascending/Descending is sent the same way. The Builder's *Sort* list offers only the fields the schema lists as sortable (`sortableFields`), and says so when the index lists none; a sort saved earlier is read as before.
- The action node, trigger and credential are now labelled **Enterspeed Core**, **Enterspeed Core Webhook Trigger** and **Enterspeed Core API** (previously **Enterspeed**, **Enterspeed Webhook Trigger** and **Enterspeed API**), to tell them apart from the upcoming Enterspeed Context Graph node. Newly added nodes get the default name "Enterspeed Core". Only display names changed — the internal names `enterspeed`, `enterspeedTrigger` and `enterspeedApi` are unchanged, so existing workflows and credentials need no action and existing nodes keep their names.

### Fixed

- **Enterspeed Context Graph**: a failed request kept only its status code in a real n8n, so the Context Graph's own message (a problem's `detail`, an upload refusal's reason), a `503`'s `Retry-After` and a `304`'s `ETag` were lost: a busy Delivery read was never retried, and a `304` came out with no headers. Every request is now read in full and a failed status is handled by the node.

## [0.1.1] — 2026-08-17

### Added

- Example workflow: Contentful → Enterspeed ingestion (`workflows/templates/ingest-contentful-into-enterspeed.json`), syncing entry and asset publish/unpublish/delete events across locales.
- Automated npm publishing via GitHub Actions (`.github/workflows/publish.yml`) with npm provenance, ahead of n8n's 1 May 2026 requirement for verified community nodes.
- **Enterspeed** node is now usable as an AI agent tool (`usableAsTool: true`), so agents can invoke Ingest/Delivery/Query/Route operations directly.

### Changed

- **Breaking:** package renamed from `n8n-nodes-enterspeed` to the scoped `@enterspeed/n8n-nodes-enterspeed`. Update the install command (`npm install @enterspeed/n8n-nodes-enterspeed`) and the Community Nodes package name in n8n's UI accordingly.
- `workflows/templates/fetch-transform-reingest.json` example workflow now includes a `Verify Data` step that validates the re-ingested `productMetadata` matches the properties sent from the metadata source entity, so the fetch → enrich → re-ingest pattern is demonstrated end-to-end.
- **Entity — Delete / Delete Entities (Bulk)** now always merge `deleted: true` onto whatever the Ingest API's delete response returned, instead of passing the raw response through unchanged.

### Fixed

- **Enterspeed** node now surfaces the underlying Enterspeed API error (via `NodeApiError`) instead of the generic Axios "Request failed with status code X" message, so failures like a 422 validation error are actionable.
- `scripts/setup.mjs` now updates the Enterspeed credential in place when re-run — e.g. after rotating API keys in `.env` — instead of skipping silently and leaving the old keys in place.

## [0.1.0] — 2026-06-25

### Added

- **Enterspeed** action node with Ingest (Save/Delete), Delivery, Query and Routes operations.
- **Enterspeed Trigger** polling node — emits new/changed items from a Query index on a schedule, with configurable change-detection field and baseline-on-first-poll behaviour.
- `EnterspeedApi` credential type supporting Environment API Key, Source API Key and host overrides for dedicated tenants.
